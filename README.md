# 초음파 공중부양 시뮬레이션

마주 보는 40 kHz 초음파 발생기 2개 사이의 정상파가 스티로폼 공을 붙잡는 현상을 계산하고 보여주는 웹 시뮬레이션입니다.
음향장 → Gor'kov 퍼텐셜 → 음향 방사력 → 공의 운동이 하나의 계산 흐름으로 이어지고, 각 단계를 해석해와 비교해 검증했습니다.
사양은 [`SPEC.md`](SPEC.md)에 있습니다.

**사이트**
- 2D 단면: https://yanggeonwoo.github.io/supersonic/
- 3D: https://yanggeonwoo.github.io/supersonic/3d.html (GPU 3D 격자, 횡방향 안정성, 밀림 효과, 발생기 기울기·어긋남)
(`main`에 push하면 GitHub Actions가 테스트 → 빌드 → `gh-pages` 브랜치로 자동 배포)

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # physics 검증 (Vitest)
npm run build      # 타입 검사 + 배포용 빌드 (dist/)
npm run test:e2e   # 화면 자동 테스트 (Playwright, 처음 한 번 npx playwright install chromium)
```

`?noworker`를 붙이면 Web Worker 대신 메인 스레드에서 음향장을 계산합니다(디버깅용).

**발표용 시작값**: 주소에 `?dia=1.2&drive=1&rho=25`처럼 공 지름(mm), 구동 세기, 공 밀도(kg/m³)를 붙이면 그 값으로 시작합니다(2D·3D 공통, 슬라이더 범위로 자름). "모두 기본값으로"를 누르면 이 시작값으로 돌아갑니다.

## 화면

- **메인 뷰**: x-z 단면 히트맵(압력 진폭 |P| / 퍼텐셜 U / 순간 압력 Re P(t)), 발생기, 마디 보조선(점선), 공.
  "힘 화살표"를 켜면 음향 방사력 + 중력(흰색)과 공이 받는 알짜힘(노란색)이 보입니다.
  순간 압력 애니메이션은 시각화용 1 Hz로 돌며 공의 운동 시간과는 관계없습니다.
- **축 위 퍼텐셜과 힘**: 축(x = 0) 위 U(z), F_z(z), mg 기준선, 공의 현재 z.
- **발생기 간격과 공진**: 공진 이득 G(d)와 현재 d. "가장 가까운 공진 거리로 맞추기"는 d를 λ/2의 정수배로 맞춥니다.
- **무게 늘리기**: 공 밀도를 서서히 늘려 부양 한계에서 떨어지는지 보여줍니다(사양 외 추가 기능).
  - **부양 한계는 2D 장 기준**입니다(`src/sim/limits.ts`). 공이 있는 덫 아래에서 축 방향 실제 힘(Gor'kov + 밀림)의 최댓값이 mg가 되는 무게입니다.
  - 1차원 해석식(F_max = mg) 한계의 약 77~80%이고, 화면에 두 값을 함께 보여줍니다. 유한 발생기의 근접장 때문에 실제 장의 힘이 해석식보다 약합니다.
  - 속도 1× / 2× / 5× / 10×를 고를 수 있습니다(1×는 한계까지 약 20초). 배속은 무게 증가와 공의 운동을 같은 배율로 빨리 재생합니다.
  - 공이 덫에 있는 동안은 내부 시뮬레이션을 32배 빠르게 돌려 준정적으로 만듭니다. 화면 시간 배율(0.05)대로만 돌리면 공이 무게 변화를 따라가지 못해 한계의 117%에서야 떨어졌습니다.
  - 그 결과 모든 배속에서 한계의 98.6~100%에서 떨어집니다.
  - "떨어진 무게"는 공이 덫(마디 아래 λ/4)을 벗어나는 순간의 값입니다. 그 단계에서 가속을 멈추므로 낙하 장면은 원래 속도로 보입니다.
- **상태 칸**: 부양 중이어도 공이 축에서 0.5 mm 넘게 벗어나 있으면 "부양 (축 밖)", 3D에서 횡방향이 불안정하면 "부양 (옆으로 불안정)"과 설명을 함께 보여줍니다.
- **공 크기 안내**: ka ≥ 0.5(40 kHz에서 지름 약 1.4 mm 이상)이면 Gor'kov 근사 범위 밖이라는 안내를 띄웁니다. 지름 ≥ λ/2(약 4.3 mm)이면 경고를 띄우고, "얼마나 무거워질 때까지 버틸까?"의 숫자를 흐리게 하며 "모델 범위 밖" 표시를 붙입니다. 계산 자체는 같은 Gor'kov 식이라 큰 공이라고 결과가 달라지지는 않습니다.
- **2D 기본 공 지름은 1.2 mm**(ka ≈ 0.44, 근사 범위 안)입니다. 3D 페이지와 단위 테스트의 기본값(`defaultParams`)은 3 mm(ka = 1.10)입니다.
- **음압 P0는 가정값**입니다. 구동 세기 1 = 1500 Pa를 기준으로 환산한 가상 조건이며, 구동 세기 슬라이더 아래와 수치 칸에 함께 보여줍니다.
- **발표에서 쓰는 관계** (`tests/m15_presentation.test.ts`로 확인)
  - 구동 세기 2배 → P0 2배, 부양 한계 4배(힘 ∝ P0²)
  - 공 지름을 바꿔도 "지금 무게의 N배"는 같습니다(기본 조건 22.7배). 힘과 무게가 모두 r³에 비례해 약분됩니다.
- 기본 조작: 공 놓기, 구동 세기, 간격 d, 공 지름·밀도, 위상차 φ, 힘 화살표. 나머지는 "고급 설정"에 있습니다.
- **점음원 지향성 (1 + cosθ)/2는 기본으로 켜져 있습니다**(`DEFAULT_DIRECTIVITY`). 실제 발생기에 가깝고, 면 근처 마디의 측면 불안정이 사라집니다(아래 "측면 안정성").
  보정(s_ref)은 지향성 설정별로 따로 구하므로 어느 쪽이든 기본 조건에서 P0 = 1500 Pa입니다.
  SPEC 6장 검증 테스트는 사양의 기준 모델인 지향성 off로 돌리고(`tests/helpers.ts`), 앱 기본값은 `tests/m7_defaults.test.ts`에서 따로 확인합니다.

## 구조

```
src/physics/   순수 계산 (React 의존 없음, Node에서 테스트)
  acoustics      음속, 파장, 공기 밀도
  gorkov         A층: 1차원 해석해, Gor'kov 퍼텐셜, F_max, 강성 κ
  resonance      공진 이득 G(d)(SPEC), 두 발생기 구동 공진 이득, 공진 거리 맞춤
  sourceSampling 원판 발생기 → 면적 가중 점음원, 거울상 반사 점음원
  field2d        B층: 2차원 압력장, 퍼텐셜/힘 격자, 축 위 1D 샘플
  calibration    구동 세기 보정 (s_ref, 앱 시작 시 한 번)
  integrator     C층: 속도 Verlet, 감쇠, 시간 간격
  lateral        횡방향 안정성: U(ρ), F_ρ(ρ), κ_ρ/κ_z
  scattering     진행파 복사압: 강체 구 복사력 함수 Y_p(ka) (부분파 급수)
  grid3, force3  3D 격자 형식·CPU 기준 계산, 3D 힘·덫 찾기·3×3 강성 행렬
src/sim/       음향장 캐시(scene), 공 상태(ballSim), 부양 한계(limits), 횡방향·밀림(lateralScene), Web Worker
src/state/     useSimulation: 2D/3D 페이지가 공유하는 상태 훅, 슬라이더 정의
src/components   2D 페이지: 컨트롤, 수치, 메인 뷰, 사이드 그래프, 히트맵(3D와 공용)
src/components3d 3D 페이지: Three.js 뷰, GPU 3D 장 표시(볼륨·등치면 셰이더), 강성 패널
src/gpu/         GPU 3D 격자 계산 (GLSL, WebGL2 render-to-texture)과 CPU 대조 자체 검증
index.html, 3d.html  두 페이지 (Vite 멀티 페이지 빌드, Three.js는 3D 페이지에만)
tests/         물리 검증 테스트 (Vitest, m1~m14)
e2e/           화면 자동 테스트 (Playwright, CI에서 배포 전에 실행)
```

음향장은 두 단계로 나눠 계산합니다.

1. `buildField` (무거움, Web Worker): 점음원 합으로 2D 격자와 축 위 1D 샘플. f, T, d, a_t, φ, 지향성이 바뀔 때만 150 ms 디바운스 후 다시 계산합니다.
2. `finishScene` (가벼움, 약 1 ms): 실제 세기, 퍼텐셜/힘 격자, 수치. 구동 세기, 공, R, ζ를 바꾸면 즉시 반영됩니다.

공의 위치와 속도는 React 상태에 넣지 않고 `useRef`로 들고, `requestAnimationFrame` 루프에서 Canvas에 직접 그립니다.

추가로 확인한 것:

- 기본 조건에서 F_max/mg = 28.3이므로 공은 지금 무게의 약 29.5배까지 버틸 수 있다고 해석식은 예측합니다. 무게 늘리기 시뮬레이션(2차원 장)에서는 이론 한계의 92%(구동 1.0)와 86%(구동 0.5)에서 덫을 벗어났습니다. 1×~10× 모든 배속에서 91~92%로 같았습니다.
- 2차원 모델(B층)의 축 방향 최대 힘은 해석식 F_max의 약 80%입니다(유한 크기 발생기의 근접장 효과).
- 공진 거리에서 λ/4 벗어나면 P0가 1500 Pa에서 482 Pa로 줄어듭니다(R = 0.5 가정).

## 측면 안정성 (검증 11)

**결론: 가운데 마디는 측면으로도 안정합니다. 면에 가까운 바깥 마디는 발생기가 크면 축 위에서 불안정하고, 공은 축에서 조금 떨어진 곳에 머뭅니다.**

마디에서 x = +0.3mm로 밀었을 때의 F_x/mg (지향성 off, 음수 = 복원):

| a_t \ d | 4·λ/2 | 5·λ/2 | 6·λ/2 | 8·λ/2 |
|---|---|---|---|---|
| 4 mm | −0.08 ×2 | −0.05 … −0.04 | −0.04 … −0.02 | −0.02 … −0.01 |
| 6 mm | −0.33 ×2 | −0.04, −0.20 | −0.13, −0.12 | −0.06 … −0.05 |
| 8 mm (기본) | −0.57 ×2 | **+0.12**, −0.50 | −0.18, −0.37 | −0.04 … −0.20 |
| 10 mm | **+1.01**, −0.45 | **+0.54**, −0.65 | −0.07, −0.63 | **+0.09**, −0.35 … −0.41 |

(각 칸은 바깥 마디, 가운데 마디 순서. 대칭이라 한쪽만 적음.)

- **가운데 마디**: 조사한 모든 조건에서 복원 방향입니다. 기본 조건에서 공을 놓는 곳(z ≈ 8.36 mm)은 F_x/mg = −0.50이고, x = 0.5mm에서 놓으면 축으로 돌아와 부양합니다.
- **바깥 마디**(면에서 약 0.4λ): a_t가 8mm 이상이면 축 위에서 F_x가 바깥을 향합니다. 기본 조건에서는 x ≈ 1.5mm까지 바깥으로 밀다가 그 너머에서 다시 복원되므로, 공은 **축에서 약 1.5mm 떨어진 곳에서 부양**합니다(실제 3차원에서는 고리 모양 평형).
- **원인**: 원판 반지름(8mm ≈ 0.93λ)에 비해 면과의 거리가 짧으면, 원판 가장자리에서 큰 각도로 오는 성분 때문에 근접장의 압력이 축 밖에서 극대가 됩니다. 점음원 개수나 격자 문제가 아니라는 근거는 두 가지입니다. 격자 힘과 격자 없이 직접 미분한 힘의 부호가 모든 점에서 일치하고, a_t를 줄이거나 간격을 늘리면 사라집니다.
- **지향성 (1 + cosθ)/2를 켜면** 큰 각도 성분이 약해져 바깥 마디도 복원 방향이 됩니다(F_x/mg = −0.02, 약함). 이때 바깥 마디에 놓은 공은 축으로 돌아옵니다.
- 실제 발생기는 지향성이 있으므로, 실험에 더 가까운 것은 지향성 on 쪽일 가능성이 높습니다. 다만 이 모델로는 확정할 수 없습니다. 이런 이유로 앱 기본값은 지향성 on입니다.

관련 테스트: `tests/m3_motion.test.ts`(검증 11), `tests/m6_lateral.test.ts`(스캔과 바깥 마디).

## 성능

계산 시간 (Node, 이 PC 기준):

| 조건 | 음향장 (`buildField`) | `finishScene` | 공 적분 (프레임당) |
|---|---|---|---|
| 기본 (113×92 격자, 점음원 92개) | 43~74 ms | 1.0 ms | 0.02 ms |
| d = 50mm, a_t = 10mm, 지향성 (113×224, 146개) | 180~210 ms | 1.2 ms | 0.02 ms |

브라우저 (헤드리스 Chrome, 1400×1300): 60.0 fps, 프레임 간격 중앙값 16.7 ms / 최대 17.2 ms.
순간 압력 애니메이션과 힘 화살표를 켜도 같고, 50 ms 이상 걸린 long task는 없었습니다.
음향장은 Web Worker에서 계산하므로 슬라이더를 끄는 동안에도 화면이 멈추지 않습니다.

## 3D 페이지

`3d.html`은 2D와 같은 계산(같은 `useSimulation` 훅, 같은 공 운동)을 쓰고 다음을 더합니다. 확장 계획과 검토 결과는 [`PLAN_3D.md`](PLAN_3D.md)에 있습니다.

**3D 뷰**
- 발생기, 공, 덫(고리)과 함께 **압력장을 입체로** 그립니다(단면이 아니라 3D 격자 전체). 마우스로 돌려 볼 수 있습니다.
- 장 표시는 장면 아래 도구줄에서 고릅니다.
  - **값**: 압력 진폭 |P|, 순간 압력 Re P(t)(1 Hz로 위상이 돎), 퍼텐셜 U(덫 = 저점)
  - **표현**: 볼륨(값이 큰 곳을 반투명하게 누적, 기본) 또는 등치면(기준값의 면을 불투명하게, 조명)
    - |P|: 압력 배(antinode) 덩어리
    - Re P(t): +(빨강)/−(파랑) 껍질이 위상에 따라 맥동
    - U: 덫(퍼텐셜 저점) 모양
  - **기준값**, **진하기**(볼륨), **절반 자르기**(가운데 덫을 지나는 x-z 면에서 카메라 쪽 절반을 잘라 속을 봄)
- 광선이 공에 닿으면 멈추므로 공 뒤의 장이 공 위에 덧그려지지 않습니다.

**횡방향 안정성** (오른쪽 강성 패널은 3D 격자의 3×3 강성 행렬로 판정합니다. 아래 결과는 축대칭 모델로 구한 것이며 단위 테스트로 유지합니다)
- 공이 있는 덫 높이에서 반지름 방향 U(ρ), F_ρ(ρ)를 직접 계산하고, 판정은 κ_ρ > 0이면 안정, 아니면 불안정입니다.
- 횡방향 강성 κ_ρ(축으로 되돌리는 힘)와 축 방향 강성 κ_z의 비율을 보여줍니다.
- 결과: 가운데 덫의 κ_ρ/κ_z는 **약 5.5%**입니다. 공은 축 방향보다 옆으로 약 18배 약하게 붙잡혀 있습니다.
- 지향성 off, 면 근처 덫에서는 κ_ρ < 0(불안정)이고, 공은 축에서 약 1.3~1.5 mm 떨어진 고리에 머뭅니다. 위의 "측면 안정성" 결과와 일치합니다.

**비대칭 출력과 밀림 효과 (진행파 복사압)**
- Gor'kov 퍼텐셜은 정상파의 힘만 담고, 진행파가 공을 미는 힘은 빠뜨립니다. 두 발생기 출력이 다르면 "센 쪽 → 약한 쪽"으로 진행파가 생기므로 이 힘을 따로 더합니다.
  - 식: `F = Y_p(ka) · π a² · I / c`
  - I: 시간 평균 음향 세기 = Im(P*∇P)/(2ωρ0)
  - Y_p: 강체 구의 부분파 급수로 구합니다. 작은 ka에서 (11/9)(ka)⁴, 큰 ka에서 1이고, 기본 공(ka = 1.10)은 0.56입니다.
- 3D 페이지는 기본 on, 2D 페이지는 항상 off입니다.
- 결과 (기본 조건, 지향성 off, 반사파 직접 계산 off, 아래쪽 가운데 덫):

| 위 발생기 출력 | 평형 이동 (밀림 on − off) | κ_ρ/κ_z | 횡방향 |
|---|---|---|---|
| 1.0 (같음) | +33 µm (가운데 쪽) | 5.68% | 안정 |
| 0.8 | +66 µm | 5.42% | 안정 |
| 0.5 | +146 µm | 4.63% | 안정 |
| 0.3 | +270 µm | 3.17% | 안정 |
| 0.1 | — | −1.12% | **불안정** |
| 0 (아래만) | 정상파 덫이 사라짐 | — | — |

- **출력이 같아도** 구면파가 퍼지며 약해지므로, 가운데가 아닌 덫에서는 진행파 성분이 정상파의 11~16%입니다. 이 성분이 공을 가운데 쪽으로 무게의 약 1배 힘으로 밉니다. 중력에 의한 처짐(24 µm)과 비슷한 크기입니다.
- 위 발생기 출력을 줄이면 공이 위(약한 쪽)로 밀리고, 덫 밖으로 흐르는 에너지 때문에 횡방향 복원력도 약해집니다.
- 아래 발생기만 구동하면 (반사파 직접 계산 off) 밀림 off에서는 떨어집니다. on에서는 진행파가 위로 미는 힘으로 축 밖(z ≈ 4.5 mm, x ≈ 3.4 mm)에 걸리지만, 근접장·ka ≈ 1·단순 합산 근사가 겹친 영역이라 신뢰하기 어렵습니다.
- 반사파 직접 계산(아래)을 켜면 위 발생기 면의 반사로 정상파가 남아, 아래만 구동해도 공이 축 위 덫에 뜹니다. 3D 기본값(반사·밀림 on)의 안착 위치는 2D와 2.6 µm 차이입니다.

**반사파 직접 계산 (거울상 점음원)**
- 2D(SPEC)는 반사를 세기 배율 G(d) = 1/|1 − R·e^{2ikd}| 하나로만 넣습니다.
- 3D 페이지(기본 on)는 상대 발생기 면에서 반사되는 파를 거울상 점음원으로 직접 더합니다.
  - 반사계수 R, 강체 면으로 보고 R^N ≤ 0.05까지 최대 6차를 넣습니다.
  - 2차 이상은 λ/2 간격으로 거칠게 샘플합니다.
  - 보정도 같은 모델로 해서 기본 조건 P0 = 1500 Pa입니다.
- **발견: 두 발생기를 같은 위상으로 구동하면 공진은 d = λ/2의 짝수배(nλ)에서 생기고, 홀수배에서는 오히려 약해집니다.**
  - 1차원으로 풀면 진폭은 `|1 + R·e^{i(kd+φ)}| / |1 − R²·e^{2ikd}|`입니다(`drivenPairGain`).
  - 같은 위상이면 짝수배에서 1/(1−R) = 2, 홀수배에서 1/(1+R) = 0.67입니다. 홀수배에서는 상대 발생기가 직접 낸 파와 반사파가 상쇄되기 때문입니다.
  - 거울상 계산의 P0도 φ = 0에서 3.03λ, φ = 180°에서 2.53λ에 최대가 있어 이 식과 일치합니다.
  - SPEC의 G(d)는 발생기 하나 + 반사판 모델이라 이 차이를 담지 못합니다. 그래서 기본 간격 5λ/2는 실제로는 약한 지점입니다.
  - 3D의 공진 그래프와 "공진 거리 맞추기"는 이 식(위상 φ 반영)을 씁니다. 2D는 SPEC대로 둡니다.
- 계산 시간: 점음원이 92개에서 264개로 늘어 음향장 계산이 37 ms에서 105 ms가 됩니다. 최악 조건(d = 50 mm, a_t = 10 mm, 지향성)은 약 500 ms이며, Web Worker에서 계산합니다.

**옆 방향 감쇠**
- 감쇠는 실제 공기 저항이 아니라 유효 감쇠비 ζ(가정값)로 줍니다.
- 이전에는 감쇠 계수를 위아래 강성으로만 정해, 옆 진동(강성이 약 5%)이 실효 감쇠비 0.4~0.5로 과하게 감쇠됐습니다.
- 지금은 옆 방향 감쇠를 가운데 덫의 횡방향 강성으로 따로 정해, 옆 진동도 감쇠비 ζ가 됩니다(테스트로 확인: ζ = 0.1에서 0.101).
- 그래서 축에서 0.5 mm 옆에 놓은 공이 좌우로 흔들리다 자리 잡기까지 화면 시간으로 약 7초 걸립니다.

**3D 성능**
- 장 표시는 레이 마칭이라 GPU가 없는 소프트웨어 렌더링(SwiftShader, CI)에서는 1~5 fps로 느립니다. 내장 GPU에서는 아래 'GPU 3D 격자' 성능 표를 보세요.
- 휴대폰에서는 픽셀 비율 1, 안티앨리어싱 off로 자동으로 낮춥니다.
- 3D 장면 오른쪽 위에 fps가 표시되므로 각자의 기기에서 실제 성능을 확인할 수 있습니다. 실제 노트북·휴대폰 측정은 아직 하지 않았습니다.
- 키보드 조작: 장면을 선택(Tab)한 뒤 방향키로 회전(Shift로 크게), +/−로 확대, 0으로 처음 시점입니다.
- Three.js(gzip 144 KB)는 3D 페이지에서만 받습니다.

## GPU 3D 격자 (3D 페이지 기본)

3D 페이지는 축대칭을 가정하지 않고 **3차원 격자 전체를 GPU(GLSL)로 계산**합니다. 예전의 "축대칭 (CPU)" 계산 방식은 없앴습니다. GPU(WebGL2 실수 텍스처 렌더링)를 쓸 수 없는 기기에서는 안내와 2D 페이지 링크를 보여줍니다. 계획과 진행 기록은 [`PLAN_3D.md`](PLAN_3D.md) 7단계에 있습니다.

**구성**
- **장 계산 (GPU, `src/gpu/fieldGpu.ts`)**
  - 복셀 하나를 프래그먼트 하나가 맡아, 점음원 전체(거울상 포함)의 P, ∇P(해석식), 음향 세기 I를 합산합니다.
  - 결과는 float 텍스처 2장(MRT)에 씁니다. z층을 2D 텍스처에 타일로 늘어놓고 층마다 따로 그립니다.
  - 셰이더는 mm 단위로 계산해 float32 정밀도를 확보합니다.
  - 장 변수가 바뀔 때만 다시 계산하고, 결과를 한 번 CPU로 읽어 옵니다.
- **힘·덫·공 운동 (CPU, `force3.ts`, `ballSim3.ts`)**
  - 읽어 온 격자를 삼선형 보간해 F = −∇U(+ 밀림)를 구합니다.
  - 덫은 뉴턴법으로 찾고, 3×3 강성 행렬과 옆 방향 두 주축의 고유값을 구합니다.
  - 공은 x, y, z 3차원 속도 Verlet으로 움직이며, 감쇠는 방향별로 ζ를 같게 줍니다.
- **표시 (GLSL, `gpuVisuals.ts`)**
  - 3D 텍스처를 레이 마칭으로 직접 샘플합니다. 볼륨은 앞에서 뒤로 누적, 등치면은 부호가 바뀌는 구간을 이분법으로 다듬고 기울기로 법선을 구합니다.
  - 값(|P| / Re P(t) / U)은 화면의 표시 모드를 따릅니다. 화면 좌표 지터로 줄무늬를 없앱니다.
- **비대칭 조건**
  - 위 발생기 기울기(x축 둘레, 0~6°)와 옆 어긋남(x, 0~3 mm), 공을 놓는 방향
  - 점음원별 방사 법선으로 지향성 (1 + n·r̂)/2를 일반화했습니다.
  - 기울어진 면에 대해서도 거울상 반사를 일반 평면 반사로 계산합니다.
- **격자 해상도**: 낮음 λ/16(8만 복셀), 보통 λ/24(27만, 기본), 높음 λ/40(117만). 휴대폰은 낮음이 기본입니다.

**검증**
- **GPU = CPU**: 무작위 300점에서 CPU `evalField`와 비교한 상대오차는 다음과 같습니다(`?selftest`로 화면에서도 확인 가능, 화면 테스트로 CI에서 확인).
  - P 7e-5, |∇P|² 1.4e-4, I 2e-4
  - 기울기·어긋남·반사를 모두 넣은 경우도 같습니다.
- **축대칭 조건에서 3D 격자 = 기존 2D** (CPU 기준 계산, λ/24)
  - 덫 위치 차이 7 µm 이내
  - 옆 강성 −3%, 위아래 강성 −5%
  - 공 안착 높이 3 µm 차이, x로 놓든 y로 놓든 같습니다.
  - 격자 미분 때문에 힘이 약 5% 작게 나옵니다(λ/40이면 약 2%).

**결과 (지향성·반사 on)**
- **위 발생기 5° 기울기**
  - 마디 면이 함께 기울어 덫이 y 방향으로 옮겨 갑니다. 면 가까운 바깥 덫일수록 크게 움직이고, 맨 아래와 맨 위는 반대 방향입니다(아래 덫 +1.4 mm, 맨 위 −0.85 mm, 가운데 +0.2~0.35 mm).
  - 가운데 덫의 옆 강성은 방향에 따라 0.6%만 달라집니다. 기울기는 옆 안정성보다 **덫 위치**를 바꿉니다.
- **위 발생기 +x 2 mm 어긋남**: 가운데 덫이 +0.9~1.1 mm, 바깥 덫은 +1.8(아래)·+0.25 mm(위) 옮겨 갑니다.

**성능 (Intel Iris Xe 내장 GPU, 반사 포함 264 점음원)**

| 해상도 | 복셀 | 장 계산 (그리기 + 읽기) | 화면 (단면 / 볼륨 / 등치면, 단면은 지금 없음) |
|---|---|---|---|
| 낮음 λ/16 | 8만 | 25 ms | 60 fps |
| 보통 λ/24 | 27만 | 40~55 ms | 60 / 60 / 60 fps |
| 높음 λ/40 | 117만 | 약 145 ms | 60 / 60 / 60 fps |

같은 보통 해상도를 CPU(Node)로 계산하면 약 3초입니다. GPU가 없는 소프트웨어 렌더러(CI)에서는 장 계산이 약 0.3~0.8초이고, 볼륨 렌더링은 매우 느립니다(약 2 fps).

## 한계

- 공 지름 3mm에서 ka ≈ 1.1이라 Gor'kov 근사(ka ≪ 1, 이 주파수에서 지름 약 1.4 mm 이하)가 엄밀하지 않습니다. **정량값이 아니라 경향을 보여주는 모델**입니다.
- 공 자체의 산란(공과 발생기 면 사이 다중 반사)은 넣지 않았습니다. 정량적으로 맞추려면 경계요소법(BEM) 같은 수치 해석이 필요합니다.
- 3D의 거울상 반사는 발생기 면을 무한 평면으로 봅니다. 실제 원판(반지름 a_t)보다 반사가 조금 크게 들어갑니다.
- 2D 페이지는 SPEC의 공진 이득 G(d)를 그대로 씁니다. 같은 위상 구동에서는 λ/2 홀수배를 공진으로 잘못 보는 단순 모델입니다(위 "반사파 직접 계산").
- 가정값: 반사계수 R = 0.5, 감쇠비 ζ = 0.1, 기준 압력 1500 Pa, 입자 체적탄성률 1e8 Pa. 공진 이득 G(d)는 다중 반사를 단순화한 모델입니다.
- x-z 단면(축대칭 가정)만 계산합니다. 공과 발생기 면 사이의 산란, 음향 유동, 공의 회전은 무시합니다.
- 면에서 λ/8 이내는 점음원 근사가 깨지므로 계산하지 않고, 이 구간에서는 음향 방사력을 0으로 둡니다.
- B층 힘은 격자(λ/40) 중앙 차분과 쌍선형 보간이라 해석값보다 약 2% 작을 수 있습니다.
- 실제 공기 저항만으로는 진동이 거의 멈추지 않으므로 유효 감쇠(가정값)를 씁니다. 공의 운동은 기본 0.05배속으로 재생됩니다.
- 면 근처 마디의 측면 안정성은 발생기 크기와 지향성 가정에 민감합니다(위 "측면 안정성").
- 진행파 복사압(3D 페이지)은 공을 강체 구로 보고 정상파 항에 단순히 더한 근사입니다(교차항 무시).
- 3D 페이지(GPU 3D 격자)는 위 발생기의 기울기(x축 둘레)와 x 어긋남만 다루고, 발생기 배열은 다루지 않습니다.
- 3D 페이지의 아래 그래프와 음압·마디 수치는 축대칭 계산의 x = y = 0 수직선 값입니다.
